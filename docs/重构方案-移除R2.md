# 重构方案：移除 R2，改为 HuggingFace + Telegram 存储

> 状态：**已实施**（2026-11-27）。默认存储 `tg`，设置页可切换 `tg` / `tg+hf` / `hf`。
> 触发原因：Cloudflare R2 开通需绑卡，用户不绑卡 → 彻底移除 R2。
> 元数据载体：**方案 B1 = Workers KV**（绑定 `env.META`，图片字节只在 HF / TG，元数据进 KV）。

## 0. 为什么必须引入 KV（一句话）

R2 在本代码里承担两类职责：**图片字节**（可挪到 HF/TG）和**元数据/小对象**（HF、TG 都装不下）。后者必须找新载体，KV 是唯一免绑卡、Workers 原生、改动最小的选择。

HF 装不下元数据的硬依据（源码已写明，非推测）：
- `settings.js:9` — HF bucket 不存 customMetadata、不支持条件请求，设置与缩略图离不开 R2
- `huggingface.js:16-17` — HF 不支持 If-None-Match/If-Modified-Since；丢弃 x-amz-meta-*（customMetadata 无处安放）

> 调研校对（scout 报告）：R2 直接触点共 **51 个语句 / 38 个调用点**，分布 `api.js`(34)、`serve.js`(8 bucket + 4 路由)、`stores.js`(5)、`settings.js`(2)。`auth.js` / `mime.js` / `index.js` 完全不碰桶（`index.js:10` 只用 `env.ASSETS`），改动面收敛。**确认「零新绑定不可行」**：元数据层必须有 KV 或 D1，纯 HF+TG 装不下。
- `api.js` 的 list / delete / 统计依赖 customMetadata（`name`、`size`、`stub` 标记）→ KV 接管

## 1. 目标存储模型

| 层 | 载体 | 内容 |
|---|---|---|
| **图片字节** | HuggingFace bucket（主） / Telegram（备） | 用户上传的图片原字节 |
| **元数据** | Workers KV | settings.json、`.tg/<key>` `.hf/<key>` 清单、`.thumb/<key>` 缩略图、gone 删除名单、`.hfq/<key>` 待归档队列 |
| **公开读取** | Cache API（边缘） | 不变，仍是一年 immutable + no-transform |

存储模式（`settings.storage`）收敛为三种，**默认 `tg`**，设置页可切换：
- `tg`（**默认**）— 字节只进 TG 频道，不占对象存储
- `tg+hf` — 字节进 TG（主），另归档一份到 HF（容灾）
- `hf` — 字节只进 HF bucket

> 用户已确认：默认 TG、设置页可切换；HF/TG 谁主谁备随所选模式变化。HF 主存是实验档（读限约 16 次/秒、单文件 30 MiB），故不作默认。

## 2. KV schema 设计

命名空间绑定：`env.META`（wrangler.jsonc 加 `kv_namespaces`）。

| KV key | value | 说明 |
|---|---|---|
| `settings` | JSON | 原 `.imghub/settings.json` 整体搬过来 |
| `manifest:<key>` | JSON | 字节位置与取回信息：`{loc:'tg'\|'hf', size, httpMetadata, chunks?（TG 分片）}`。一条清单一把钥匙，`loc` 决定读路径走 TG 还是 HF；`tg+hf` 模式下字节双份但清单仍一条（`loc` 记主存，备份清单信息并入同一 JSON） |
| `queue:hf:<key>` | JSON | 待归档标记（原 `.hfq/<key>`） |
| `thumb:<key>` | WebP bytes | 浏览器生成的缩略图（原 `.thumb/<key>`） |
| `gone` | JSON `[[key,ms],...]` | 删除名单（原 settings.gone，独立出来减轻 settings 体积） |

图片字节**不进 KV**（KV value 上限 25 MB 且按读计费，不适合存图）。`customMetadata` 里原来存的 `name`/`size`/`stub` 标记，全部并入对应 manifest JSON。

## 3. 代码改动面

| 文件 | 改动 |
|---|---|
| `src/stores.js` | **重写**。删掉 R2 路由表概念（`configStore`/`writeStore`/`storesFor` 原按「主桶+时间路由」）。改为字节存储选择器 `byteStore(env)` → 返回 HF 或 TG 后端句柄。设置不再从桶读，改走 `meta.js` |
| `src/meta.js` | **新增**。KV 抽象层：`getMeta`/`putMeta`/`deleteMeta`/`listMeta(prefix)`/`getSettings`/`putSettings`。把散落各处的 `configStore(env).bucket.*` 元数据调用收口 |
| `src/settings.js` | 设置读写从「主桶 JSON 对象」改为 `meta.js` 的 KV。`SETTINGS_KEY` 保留常量但语义变为 KV key `settings` |
| `src/serve.js` | 读路径 `Cache API → HF(主)/TG → TG 备份 → 回源`。删掉 R2 分支与占位对象逻辑；manifest 从 KV 读。Range/ETag 对 HF 走「上游判 Range」不变 |

| `wrangler.jsonc` | 删 `r2_buckets`；`vars.STORES` 删除；加 `kv_namespaces` 绑定 `META`；`assets`/`ratelimits`/`crons`/`keep_vars` 保留 |
| `public/*` | settings 页存储模式选项从「r2/tg/hf 组合」改为「hf / hf+tg / tg」；i18n 同步 |

## 4. 不变的部分

- 鉴权（`auth.js` HMAC cookie）、限速（`LOGIN_LIMITER`）、CORS、错误码约定
- 浏览器端压缩 / 实况照片 / HDR / 缩略图生成（`public/live.js`、`thumb.js` 等）
- HF 的 S3 SigV4 签名实现（`huggingface.js` 核心算法）
- Cache API 读路径与防盗链逻辑骨架

## 5. 风险与代价（必须知情）

| 风险 | 影响 | 缓解 |
|---|---|---|
| **HF 读限 16 次/秒** | 缓存未命中时代读慢、高并发会 429 | Cache API 挡在前面（一年 immutable），实际未命中少；本就低流量个人博客 |
| **HF 单文件 30 MiB** | 大图/视频存不了 HF | 超限自动落 TG（TG 单文件 100 MB） |
| **KV 最终一致性 ~60s** | 设置改动/删除名单全球生效有延迟 | 对图床元数据可接受；gone 名单延迟不影响已删对象的读（读路径先查 KV gone） |
| **KV 免费额度** | 写 1000 次/天、读 10 万次/天（免费） | 元数据读写频率低；缩略图只在生成时写一次 |
| **偏离上游** | 以后 Sync fork 会冲突 | 本 Fork 已定位「个人自用」，接受不再平滑跟随上游 |
