# Cloudflare R2 配额与计费

> 核对日期：**2026-11-27**。数字全部取自 Cloudflare 官方文档（R2 Pricing 页标注最后更新 2026-10-30），价格与额度可能调整，签约/扩容前请以官方页面为准。文中「[本项目]」指 CF-ImgHub；与 HuggingFace 的横向对比见 `Huggingface-主存代价分析.md`。

## 0. 一句话结论

- **免费额度内 \$0**，但 R2 必须先「订阅」：在面板走一次 checkout、绑付款方式才能建桶，免费额度内的账单是 \$0。
- 免费额度只覆盖 **Standard** 存储：10 GB-month 存储 / 100 万 Class A / 1000 万 Class B，**出口流量永久免费**。
- 超出后按量计费，无月费；个人博客量级通常每月几美分到 1 美元。

---

## 1. 是否必须付费

| 问题 | 答案 |
|---|---|
| 能免费用吗 | 能，每月免费额度内的用量不计费 |
| 需要绑卡吗 | **需要**。官方 Get started：「You need a Cloudflare account with an R2 subscription… Complete the checkout flow to add an R2 subscription」 |
| 有月租/最低消费吗 | 没有（账单按实际用量，免费额度内为 \$0） |
| 出口流量收费吗 | **不收费**，任何存储类别、任何量都免费——这是 R2 相对 S3 的核心优势 |
| 删除对象收费吗 | 免费（`DeleteObject` / `DeleteBucket` / `AbortMultipartUpload` 不计费） |

---

## 2. 免费额度（每月，仅 Standard）

| 项目 | 免费额度 |
|---|---|
| 存储 | **10 GB-month / 月** |
| Class A 操作（写类） | **1 000 000 次 / 月** |
| Class B 操作（读类） | **10 000 000 次 / 月** |
| 出口流量（egress） | 免费、不限量 |

注意：

- 免费额度**只适用 Standard 存储**，Infrequent Access 不享受；
- 「GB-month」是**按天取峰值再按月平均**，不是月末快照：`1 GB×5 天 + 3 GB×25 天 = 1×5/30 + 3×25/30 = 2.66 GB-month`；
- 鉴权失败的请求不计费；
- 额度按账号计、按月重置（不是按桶）。

## 3. 价格（超出免费额度后）

|  | Standard | Infrequent Access |
|---|---|---|
| 存储 | \$0.015 / GB-month | \$0.01 / GB-month |
| Class A 操作 | \$4.50 / 百万次 | \$9.00 / 百万次 |
| Class B 操作 | \$0.36 / 百万次 | \$0.90 / 百万次 |
| 数据取回（retrieval） | 无 | \$0.01 / GB |
| 出口流量 | 免费 | 免费 |
| 免费额度 | 有（见上） | **无** |
| 最短存储期 | 无 | **30 天**（不足也按 30 天计） |

其他：

| 项目 | 价格 |
|---|---|
| 桶数量 | 前 100 000 个包含在套餐内，超出 \$0.10 / 桶 / 月 |

常用换算：100 GB ≈ \$1.50/月（0.015 × 100）；1 TB ≈ \$15.4/月（1024 GB）；1000 万次 Class A ≈ \$45。

## 5. 计费口径：什么算 A、什么算 B

**Class A（写类，贵）**：`ListBuckets`、`PutBucket`、**`ListObjects`**、`PutObject`、`CopyObject`、`CreateMultipartUpload`、`UploadPart`、`UploadPartCopy`、`ListParts`、`ListMultipartUploads`、`CompleteMultipartUpload`、`LifecycleStorageTierTransition`、`PutBucketEncryption`、`PutBucketCors`、`PutBucketLifecycleConfiguration`。

**Class B（读类，便宜）**：`GetObject`、`HeadObject`、`HeadBucket`、`UsageSummary`、`GetBucketEncryption`、`GetBucketLocation`、`GetBucketCors`、`GetBucketLifecycleConfiguration`。

**免费**：`DeleteObject`、`DeleteBucket`、`AbortMultipartUpload`。

> 容易踩的点：**列对象（ListObjects）算 Class A**，不是 B。管理页翻页、统计接口、归档状态统计都会消耗 A 类额度。

## 6. [本项目] 对照

### 6.1 10 GB 能存多少图

| 平均单图（压缩后） | 10 GB ≈ |
|---|---|
| 150 KB | 约 6.8 万张 |
| 250 KB | 约 4.1 万张 |
| 500 KB | 约 2 万张 |

### 6.2 操作映射

| 项目里的动作 | R2 调用 | 类别 |
|---|---|---|
| 上传一张图 | `PutObject` | A ×1 |
| 上传后生成并保存缩略图 | `PutObject`（`.thumb/<key>`） | A ×1 |
| 管理页翻页 / `/api/stats` | `ListObjects` | **A**（每页 1 次，stats 会翻多页） |
| 设置读写 | `GetObject` / `PutObject` | B ×1 / A ×1 |
| 打开图片（缓存未命中） | `GetObject` | B ×1 |
| 打开图片（边缘缓存命中） | 不进 R2 | 0 |
| 删除图片 | `DeleteObject` | 免费 |

`/file/*` 的响应带 `Cache-Control: public, max-age=31536000, immutable, no-transform`，所以**热门图基本不消耗 B**；B 类主要花在冷图和首次访问上。

### 6.3 示例账单

假设：存 20 GB、月上传 5 万张（含缩略图约 10 万次 A）、冷读 200 万次。

```
存储     (20 − 10) GB × $0.015      = $0.15
Class A  10 万  ≤ 100 万免费         = $0
Class B  200 万 ≤ 1000 万免费        = $0
──────────────────────────────────────────
合计                                  ≈ $0.15 / 月
```

### 6.4 什么时候开始付钱

| 触发条件 | 之后的价格 |
|---|---|
| 存储 > 10 GB | 超出部分 \$0.015/GB-month |
| Class A > 100 万/月 | 超出部分 \$4.50/百万次 |
| Class B > 1000 万/月 | 超出部分 \$0.36/百万次 |

估算公式：

```
费用 ≈ max(0, 存储GB − 10) × 0.015
     + max(0, A次数 − 1_000_000) / 1_000_000 × 4.50
     + max(0, B次数 − 10_000_000) / 10_000_000 × 0.36
```

## 7. 容易混的一笔账：R2 免费 ≠ Worker 免费

图片请求先经 Worker（`wrangler.jsonc` 的 `assets.run_worker_first` 覆盖 `/file/*`、`/api/*`），**即使命中 Cache API 也计一次 Worker 请求**。

| | Workers 免费档 | Workers 付费档 |
|---|---|---|
| 请求 | 100 000 / 天（≈300 万/月） | 不限量，\$5/月 起 |
| CPU | 10 ms / 次 | 30 s 默认，最长 5 min |

本项目的图片压缩在浏览器里完成，Worker 侧 CPU 很小，不会撞 10 ms；瓶颈只会是**请求量**。博客级流量免费档够用，被大规模热链时才需要升级。

另外：HF 归档的 cron（`0 */6 * * *`）同样是 Worker 调用——付费档按请求计费，免费档每个 cron 只有 **10 ms CPU**、账号最多 **5 个 cron 触发器**，所以免费档下 `hfSweep`（列标记 + 逐张补归档）可能吃力，需要补归档时更适合在设置页手动点「开始归档」。
